# 双人分工

两人开工时认领一个角色，并在下面填写。每层的封装与解封装分别由两人负责，方便交换样例并互相检查。

| 角色 | 姓名 | GitHub 用户名 |
| --- | --- | --- |
| A | 待填写 | 待填写 |
| B | 待填写 | 待填写 |

## 同学 A

| 文件 | 任务 | 给同学 B 的交接内容 |
| --- | --- | --- |
| `udp_encode.c` | 写入端口、长度和校验和，拼接应用数据 | 一份 UDP 十六进制样例及预期端口、长度和原文 |
| `ipv4_decode.c` | 解析 IPv4 首部、校验字段、定位 UDP | UDP 数据的起始位置及长度，以及从首部读出的源、目的 IP |
| `ethernet_encode.c` | 构造 Ethernet II 首部，补齐数据区，写入 FCS | 一个完整帧样例和预期帧长、填充长度 |
| `pdu.h`、`wire.c` | 根据双方确认的约定提交公共头文件，维护字节序和校验函数 | 可供双方编译的函数声明与实现 |

报告负责封装部分。说明每层构造了哪些字段，用实际终端输出展示 UDP、IPv4 和以太网帧的长度，以及完整帧的十六进制。

## 同学 B

| 文件 | 任务 | 给同学 A 的交接内容 |
| --- | --- | --- |
| `ipv4_encode.c` | 构造 IPv4 基本首部，写入总长度、TTL、协议号和校验和 | 一份 IPv4 十六进制样例及预期源、目的 IP 和总长度 |
| `ethernet_decode.c` | 解析 MAC、EtherType 和 FCS，向上交出以太网数据区 | 可用于调用 IPv4 解封装的字节指针和长度 |
| `udp_decode.c` | 解析 UDP 首部，验证校验和，交出应用数据 | 应用数据的起始位置、长度及与原文核对的结果 |
| `main.c` | 设置演示数据，串联封装和解封装，打印各层长度、完整帧和还原结果 | 可一次运行的演示入口，以及报告所用的联调输出 |

报告负责解封装部分。展示字段值及含义、三层校验结果、还原消息和错误测试。合稿前一起核对 PDF 中的输出与最终代码版本。
